# MeetPod UI 디자인 스펙

**Date:** 2026-05-13
**Status:** Approved (brainstorming)
**Owner:** Harry Kim

## 1. 디자인 컨셉

**"HERMES 오렌지 위의 노랑 메신저"** — 강한 단일 브랜드 컬러로 차별화한 일정·위치·채팅 통합 앱.

- 카카오톡 노랑처럼 **전체 화면 배경 = HERMES 오렌지(#FF6900)**. 흰 카드가 그 위에 떠 있는 형태.
- 본인 메시지 = 카톡 노랑(#FEE500), 친근하고 익숙.
- 샤프한 모서리(radius 4-8) + 다크 플로팅 탭바. Z세대 톤.

## 2. 디자인 토큰

### 2.1 색상

```ts
// mobile/src/theme/colors.ts
export const colors = {
  // 브랜드
  brandPrimary:    '#FF6900',  // HERMES — 앱 배경
  brandPrimaryDark:'#E55A00',  // 헤더 영역 (구분용)
  brandSecondary:  '#FEE500',  // 카카오 노랑 — 본인 메시지·CTA

  // 텍스트
  ink:             '#1F1B0F',  // 본문 (검정 아님, 따뜻한 차콜)
  inkInverse:      '#FFFFFF',  // 오렌지 위 텍스트
  muted:           '#64748B',  // 부가 정보
  mutedLight:      '#94A3B8',  // placeholder

  // 표면
  surface:         '#FFFFFF',  // 카드
  surfaceSubtle:   '#F8FAFC',  // alt 카드, divider 부근
  surfaceDark:     '#1F1B0F',  // 탭바, 작은 액션 단추 배경

  // 상태
  success:         '#3DD68C',  // 진행중, 성공
  warning:         '#F59E0B',
  danger:          '#EF4444',
  info:            '#6366F1',  // 인디고 — 정보, 보조 강조

  // 경계
  border:          '#E2E8F0',
  borderOnOrange:  'rgba(255,255,255,0.25)',
} as const;
```

### 2.2 타이포그래피

- **폰트:** `Pretendard` (한글 모던 디폴트). Expo에서 `@expo-google-fonts/pretendard`로 로드. 시스템 폰트 fallback.
- **스케일:** sm 12 / base 14 / md 15 / lg 17 / xl 19 / 2xl 22 / 3xl 26
- **굵기:** regular 400 / medium 500 / semibold 600 / bold 700 / black 800
- **컨벤션:**
  - Nav 타이틀: `2xl/800`
  - Section 타이틀: `lg/700`
  - 카드 타이틀: `md/700`
  - 본문/메시지: `base/400-500`
  - 메타/캡션: `sm/400 muted`
  - 뱃지: `10px/700 uppercase`

### 2.3 간격

4·8·12·16·24·32 스케일. `spacing(1)=4px`. 카드 padding `spacing(3.5)=14px`, 행 간격 `spacing(2)=8px`.

### 2.4 모서리

- **Sharp 4-8 스케일**: `xs 4` (뱃지/단추/카드/입력 등 기본) · `sm 6` (FAB) · `md 8` (모달, 탭바 캡슐, phone frame)
- 둥근 99(원/pill)은 **아바타·인터널 칩에만** 한정 (전체 톤이 sharp이므로 예외 처리).

### 2.5 그림자

- `shadowCard`: 거의 없음 (orange 배경에 흰 카드는 충분히 대비됨). 필요 시 `0 1px 2px rgba(0,0,0,0.04)`.
- `shadowHeaderSeparator`: 헤더 하단에 `0 4px 8px rgba(31,27,15,0.18)` — **B 옵션은 사용 안 함** (헤더 색상으로 구분). 다른 화면 hero 카드 등에 활용 가능.
- `shadowFloatingTabbar`: `0 8px 20px rgba(0,0,0,0.18)`.

## 3. 핵심 컴포넌트

### 3.1 ScreenContainer

모든 화면의 루트. 배경 `brandPrimary`. SafeArea + 헤더 + 본문 + 탭바를 stack.

```tsx
<ScreenContainer headerTitle="약속" headerSubtitle="3건 예정" headerAction={<HeaderButton icon="+" />}>
  {/* 본문 */}
</ScreenContainer>
```

### 3.2 Header

- 배경 `brandPrimaryDark (#E55A00)`로 본문과 구분.
- 좌측: 뒤로가기 화살표 (스택 깊이 ≥1) 또는 큰 타이틀.
- 우측: 1개의 액션 단추 (`SurfaceDark` 배경 + `brandSecondary` 아이콘, 28×28, radius 4).
- 서브타이틀(`navSub`)은 헤더 영역에 함께 포함되어 같은 진한 오렌지.
- 패딩: 상단 14 · 좌우 16 · 하단 12. 상태바는 SafeAreaView로 처리.

### 3.3 Card

흰 표면. radius 4. 패딩 14. 행 간격 8. orange 배경 위에서 그림자 없음.

배리언트:
- `<Card>` 기본
- `<Card variant="hero">` 큰 헤더 카드 (제목 + 메타 + 액션). 패딩 16-18.
- `<Card variant="row">` 리스트 행 — 더 컴팩트 (패딩 12-14).

### 3.4 Button

| variant | 배경 | 텍스트 | 사용처 |
|---|---|---|---|
| `primary` | `brandSecondary #FEE500` | `ink` | 주요 CTA (만들기, 시작) |
| `ghostOnOrange` | `rgba(255,255,255,0.18)` | `inkInverse` | 보조 액션 (오렌지 위) |
| `dangerOnSurface` | `surface` | `danger` | 취소·삭제 |
| `dark` | `surfaceDark` | `brandSecondary` | 헤더 액션 단추 |

- 모서리 radius 4, padding `12 16`, font `md/700`, 텍스트 가운데 정렬.
- Press 시 opacity 0.85 (전용 Pressable wrapper).

### 3.5 Badge

`10px/700`, padding `3 7`, radius 4.

| 이름 | 배경 | 텍스트 |
|---|---|---|
| `today` | `brandSecondary` | `ink` |
| `live` | `success` | `inkInverse` |
| `ended` | `mutedLight` | `inkInverse` |
| `cancelled` | `danger` | `inkInverse` |

### 3.6 MessageBubble

- 상대: `surface` 배경 / `ink` 텍스트 / radius 4 / max-width 72%.
- 본인: `brandSecondary` 배경 / `ink` 텍스트 / `font-weight 600`.
- 이미지/장소 카드는 버블 padding 0 + 내부 자체 padding (기존 패턴 유지).
- 그룹 안 동일 발신자 연속 메시지는 위쪽 radius 작게 (말풍선 묶음) — Phase 2.

### 3.7 TabBar

- **플로팅 다크 캡슐.** 화면 하단 12px 안쪽에 떠 있는 형태.
- 컨테이너: `surfaceDark` 배경, radius 8, padding 5, `shadowFloatingTabbar`.
- 탭 4개 균등 분배.
- 비활성: `rgba(255,255,255,0.6)` / icon 17 / label 10/600.
- **활성: `brandSecondary` 배경 + `ink` 텍스트, radius 6.** 단일 탭만 강조.
- 안전영역 하단(home indicator)와 겹치지 않게 SafeAreaInsets.bottom + 12.
- 본문 ScrollView는 `paddingBottom: tabbarHeight + 24`로 마지막 항목이 가려지지 않게.

### 3.8 Avatar

- 28×28 (멤버 칩) / 40×40 (프로필 행) / 64×64 (Me 화면).
- **radius 4** (sharp 톤 유지). 원이 아닌 squircle.
- 사용자별 결정론적 배경색 (`info`, `success`, `brandSecondary`, `surfaceDark` 4색을 user_id hash로 순환). 텍스트는 이니셜(이름 첫 2글자).
- 사진 있으면 사진. 없으면 이니셜 자동.

### 3.9 Input

- 흰 배경, radius 4, padding `10 12`, font `base/400`, border `1px solid border`.
- Focused: border `brandPrimary 2px`.
- 채팅 입력바: 화면 하단 sticky, 좌측 + 아이콘, 우측 전송 (브랜드 노랑 작은 단추).

### 3.10 PlaceCard

채팅의 장소 메시지 또는 약속 상세에 들어가는 작은 카드. 흰 배경, 상단 정보 + 하단 지도 미리보기 (110px). 탭하면 외부 지도 앱.

## 4. 화면별 적용 노트

### 4.1 LoginScreen
- 배경 `brandPrimary`. 큰 로고/타이틀 (3xl/800 white). 하단에 `Button primary` (Google), `ghostOnOrange` (Apple/Kakao 비활성).
- 푸터: 약관 링크 (10px white 60%).

### 4.2 OnboardingHandleScreen
- 헤더 작게. 큰 안내 텍스트 + 큰 input + Button primary "시작하기".

### 4.3 MeetupListScreen
- Header `약속` + sub `N건 예정`. 우측 액션 `+`.
- 본문: 행 카드(`Card row`), 상태 뱃지 + 제목 + 메타.
- 빈 상태: 가운데 정렬 안내 + Button primary "첫 약속 만들기".

### 4.4 MeetupDetailScreen
- Hero 카드: 제목 / 시작-종료 시간 / 참여자 아바타 가로 줄.
- PlaceCard.
- 행동 단추 묶음: `primary` (실시간 위치 / 약속 채팅) + `ghostOnOrange` (다른 보조) + 필요 시 `dangerOnSurface` (취소).

### 4.5 MeetupCreateScreen
- ScrollView. 각 필드 = 흰 카드. 라벨 흰색 → 카드 상단에. 입력 카드 내부.
- 시간 / 장소 / 위치공유 분 / 알림 / 참여자 모두 카드 패턴 통일.

### 4.6 MeetupMapScreen
- 지도 풀스크린. 상단에 sticky pill 형태로 배너 (`SurfaceDark` 배경에 흰 텍스트 — "내 위치 공유 중" 등).
- 하단 floating tabbar 위에 작은 액션(스크롤바 풀백)이 들어갈 수 있음 — Phase 2.

### 4.7 GroupListScreen / GroupDetailScreen
- MeetupList와 같은 카드 패턴. 그룹 카드에는 멤버 수 + 마지막 활동 시간.

### 4.8 ChatListScreen
- 행 카드: 좌측 아바타(공통 채팅이라 그룹/약속의 대표 색), 본문 (제목 / 마지막 메시지 / 시간), 우측 미열람 뱃지.

### 4.9 ChatRoomScreen
- 헤더에 채팅명 + 인원수(sub).
- MessageBubble 위주. 인풋바 sticky.
- 위치공유 시작 안내 배너 (`SurfaceDark` pill, 본인 메시지 영역 위에 1회) — Phase 2.

### 4.10 PlacePickerScreen
- 입력 + 결과 리스트 (흰 카드 행). 디바운스 250ms 유지.
- 디바운스 중에는 작은 spinner 표시.

### 4.11 InviteAcceptScreen
- 모달 풀스크린. 큰 정보 카드 + Button primary 수락 + ghost 거절. 상단 X 닫기.

### 4.12 ProfileScreen
- 큰 아바타(64) + 이름 + 핸들 헤더.
- 메뉴 행 (행 카드 패턴, 우측 chevron).

## 5. 구현 접근

**현재 코드(StyleSheet 기반)을 유지**하되 토큰을 별도 모듈로 분리:

```
mobile/src/theme/
├── index.ts         # export 통합
├── colors.ts        # 색상 토큰
├── typography.ts    # 폰트·스케일·굵기
├── spacing.ts       # 4·8·12·16·24·32
├── radius.ts        # xs 4, sm 6, md 8, pill 999
└── shadows.ts       # iOS/Android shadow 매핑
```

각 컴포넌트는 `StyleSheet.create()` 안에서 토큰 참조. NativeWind/Tamagui 같은 라이브러리는 **도입 안 함** (의존성 추가 없이 깔끔 유지). 만약 점점 복잡해지면 Phase 2에서 도입 검토.

**점진적 적용:**
1. 토큰 모듈 작성 + 폰트 로드
2. 공통 컴포넌트 (Button, Card, Header, TabBar, Badge, Avatar, ScreenContainer, Input) 작성
3. 화면을 1개씩 새 컴포넌트로 교체. 한 PR/커밋 = 한 화면.

## 6. 비범위 (Phase 2 이후)

- 다크모드 (전체 오렌지 위주라 다크 별도 필요)
- 애니메이션 (탭 전환 모션, 카드 등장)
- 일러스트 / 마스코트 (현재는 폰트 + 컬러로 표현)
- 다국어 (현재 한국어 고정)
- 접근성 (높은 대비 모드, 폰트 스케일 적응)

## 7. 결정 근거 (자기 참조용)

- **풀 오렌지 (A1)**: 차별화 우선. 카톡=노랑처럼 메모리에 박히게.
- **노랑 본인 버블 (E)**: 메신저 표준의 친근함 + 오렌지와 보색 쌍. 강한 정체성.
- **샤프 (S)**: 정보 밀도 높이고 어른스러움. 모서리 round로 친근함은 색상이 이미 담당.
- **다크 플로팅 탭바 (D)**: 화면 하단을 묵직하게 잡아 시각적 밸런스. 노랑 활성칩이 단일 포커스 만들어 인지 빠름.
- **헤더 다크 오렌지 (B)**: 콘텐츠와 nav를 명확히 분리. 흰 라인보다 입체감.
